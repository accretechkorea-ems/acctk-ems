## 먼저 — 지시와 실제가 다르다

지시: 「회사 2574(하나무역) 사업장에 견적 **14건**이 「사명=하나무역(회사)」로 들어가 있음」.

실제:

| | 건수 | 모습 |
|---|---|---|
| 회사 **2574** 에 직접 붙은 견적 | **0건** | 2574 에는 견적·장비·활동·담당자·포캐스트·의뢰서가 **모두 0건**이다 |
| 사명이 **대리점 줄 1767** 인 견적 | **5건** | 사명=하나무역, 대리점=빈칸 — **이 5건이 고칠 것이다** |
| 대리점이 1767 이고 사명이 실제 고객사인 견적 | **9건** | 이미 올바른 모습이다 — **손대지 않는다** |
| 합 | **14건** | 하나무역 화면이 14건으로 보이는 까닭이 이것이다 |

14 라는 숫자는 맞다. 다만 그 14건이 전부 잘못 들어간 것이 아니라, **5건만** 잘못 들어가 있고
9건은 이미 「대리점=하나무역 · 사명=실제 고객사」로 제대로 저장돼 있다. 그래서 SQL 이 건드리는
것은 **5건**이다. 9건을 함께 옮기면 이미 맞는 줄의 사명을 지우는 일이 된다.

올바른 모습(`lib/quoteCustomerPick.ts` 의 규칙, 2026-11-20부터):

```
직판    customer_id = 고른 사업장        dealer_id = null
대리점  customer_id = **E.U 사업장**      dealer_id = 고른 대리점
```

E.U 전용 칸은 없다 — 대리점 건의 수요처가 곧 E.U 다.

## 하나무역 두 줄 — 1767 과 2574

| id | 역할 | 이름 | 부모 | 붙어 있는 것 |
|---|---|---|---|---|
| **2574** | 회사(`is_parent`) | 하나무역 | 없음 | 견적 0 · 장비 0 · 활동 0 · 담당자 0 · 포캐스트 0 · 의뢰서 0 · 수리 0 · 사건 0 — **자식 줄 1767 하나뿐** |
| **1767** | 대리점(`is_agency`) | 하나무역 | **2574** | 견적 5(사명) + 9(대리점) · 담당자 1(김광옥) · 사건 2 · 장비 0 · 활동 0 · 포캐스트 0 |

2574 는 **껍데기**다. 1767 을 회사 아래 묶어 두기 위해 생긴 줄로 보인다.

### 2574 를 지우려면 1767 의 부모를 먼저 떼야 한다 — 그리고 그 값이 있다

`app/api/customer-delete/route.ts:240` 이 회사 삭제를 이렇게 막는다.

> 회사 줄은 **묶인 사업장이 없을 때만** 지운다. 숨기는 것이라도 회사가 사라지면
> 그 아래 사업장이 트리에서 길을 잃는다.

그래서 2574 를 지우려면 1767 의 `parent_customer_id` 를 비워야 한다. 그런데 그 값은
**1767 이 고객사 목록에 보이는 유일한 이유**다 — `lib/customerAgency.ts` 의
`NOT_AGENCY_ONLY = 'is_agency.eq.false,parent_customer_id.not.is.null'` 는 「대리점이 아니거나,
대리점이어도 어느 회사에 묶여 있는 줄」만 목록에 세운다. 1767 은 `is_agency = true` 이므로
부모를 떼는 순간 **고객사 목록에서 사라진다**(대리점 화면에는 그대로 남는다).

→ **판단 필요**. SQL 의 그 부분은 주석으로 두고 Kevin 이 고르게 했다:

- ㉮ **그대로 둔다** — 2574 는 남고, 하나무역은 고객사 목록에도 대리점 화면에도 보인다. 껍데기 한 줄이 남는 값.
- ㉯ **2574 를 지우고 1767 을 떼낸다** — 하나무역은 **대리점 화면에만** 보인다. 하나무역에 장비가 0대이고
  우리 고객이 아니라면 이쪽이 맞는 모습이다. 담당자 김광옥 1줄과 사건 2줄은 1767 에 그대로 남는다.

## 사명이 비면 화면이 어떻게 보이나 (8-2)

- `quotes.customer_id` 는 **NULL 을 받는다**(PostgREST 스키마의 `required` 는
  `quote_id · quote_number · quote_date · created_by` 네 칸뿐이다). DB 를 고칠 일은 없다.
- 지금 사명이 NULL 인 견적은 **0건**이다(전체 211건 · 대리점이 붙은 건 63건).
- 화면은 깨지지 않는다 — `customerDisplayName(null)` 과 `customerCompanyName(null)` 이 빈 문자열을
  돌려주고, 내 견적·실적 표는 `|| '-'` 로 받는다. 다만 **`-` 는 「사명이 아직 없다」와 「내가 못 보는 사명」을
  구분해 주지 못한다** — 그래서 사명이 비어 있을 때만 「**E.U 미지정**」으로 적게 고쳤다
  (`lib/quoteEuName.ts` 의 `EU_UNSET_LABEL`).
- 견적 **수정 모달은 이미 된다**. `hooks/quote/useQuotePrefill.ts:205` 가 대리점 건을
  `mainId = dealer_id` · `euId = customer_id` 로 읽으므로, 사명이 NULL 이면 사명 칸에 하나무역(대리점)이
  서고 **E.U 칸이 빈 채로 열린다**. 저장할 때 E.U 는 여전히 필수이므로(`app/quote/page.tsx:466`)
  Kevin 이 E.U 를 고르지 않고는 저장되지 않는다 — 비워 두는 것을 **고치라는 표시**로 쓰는 셈이다.
