# 복구 절차 — 자료가 지워졌을 때 무엇을 어떻게

**이 문서는 Kevin 없이도 따라갈 수 있게 쓴 것이다.** 명령을 위에서 아래로 그대로 치면 된다.
막히면 멈추고 사람을 부르라 — **되돌리는 작업은 또 한 번 지울 수 있다.**

---

## 0. 먼저 — 무엇이 어디에 있나

| 백업 | 무엇이 들어 있나 | 얼마나 오래 | 어디에서 |
|---|---|---|---|
| **Supabase 일일 백업** | DB **전체**(표 구조·제약·RLS·함수·자료) | **7일** | Supabase 대시보드 |
| **주간 백업**(`npm run backup`) | DB 표의 **자료**(JSON) + **스토리지 파일 전부** | 사람이 지울 때까지 | `C:\Users\admin\ems-backup\YYYYMMDD\` |

**중요한 차이**
- Supabase 일일 백업은 **7일이 지나면 없다.** 그보다 오래된 자료는 주간 백업에만 있다.
- 주간 백업의 JSON 은 **자료만**이다. 표 구조·RLS 정책·DB 함수는 들어 있지 않다
  (구조 기록은 같은 폴더의 `db-YYYYMMDD\_schema.json` 과 저장소의 `*.sql` 파일들이다).
  → **빈 프로젝트를 이 JSON 만으로 되살릴 수는 없다.** 전체 복구는 반드시 Supabase 백업이 먼저다.
- **스토리지(첨부·PDF·사진)는 Supabase 일일 백업에 들어가지 않는다.** 주간 백업이 유일한 사본이다.

폴더 안 모습:

```
C:\Users\admin\ems-backup\20261023\
  _manifest.json              무엇을 몇 줄 받았는지 (제일 먼저 열어 볼 것)
  db-20261023\
    _schema.json              표·컬럼·함수 목록(PostgREST OpenAPI 그대로)
    customers.json            표 하나 = 파일 하나, 줄 하나 = 행 하나
    quotes.json
    ... (표 62개)
  storage-20261023\
    quote-pdfs\<파일>         버킷 = 폴더, 안의 경로가 그대로
    inquiry-attachments\...
    ... (버킷 12개)
```

## 1. 백업 돌리기 — 매주 월요일 출근 직후

```
cd C:\Users\admin\acctk-ems
npm run backup
```

- **출근 직후에 돌려라.** 6분쯤 걸리고 그 사이에 누가 자료를 고치면 표마다 시각이 조금씩
  달라진다(한 시점의 사진이 아니다). 사람이 쓰지 않는 시간이 가장 깔끔하다.
- 끝에 요약이 나온다 — 표 62개 / 줄 수 / 버킷 12개 / 파일 수 / 걸린 시간.
  **실패가 한 건이라도 있으면 종료 코드가 1 이고 빨간 줄이 보인다.** 그때는 다시 돌려라.
- 두 번째부터는 **스토리지에서 이미 같은 크기로 받아 둔 파일을 건너뛰어** 훨씬 빠르다.
- 위치를 바꾸려면: `npm run backup -- D:\ems-backup` 또는 `.env.local` 에 `BACKUP_DIR=...`

**8주보다 오래된 폴더가 있으면 목록만 알려 준다.** 스크립트는 **지우지 않는다** —
지울지는 사람이 보고 판단한다(용량이 넉넉하면 그냥 둬도 된다. 한 주치가 180MB쯤이다).

### 한 벌 더 복사하라

받은 폴더를 **외장 하드나 사내 NAS 에 한 벌 더** 복사해 둔다. 이 PC 가 고장나면 백업도
같이 간다. 복사는 탐색기로 끌어다 놓아도 되고, 명령으로는:

```
robocopy C:\Users\admin\ems-backup D:\ems-backup /E /XO
```

**폴더 안에는 고객 자료가 그대로 들어 있다** — 공유 폴더·개인 클라우드에 올리지 마라.
(접속 키는 백업에 들어 있지 않다. 키는 `.env.local` 과 회사 비밀번호 금고에만 있어야 한다.)

## 2. 표 하나만 되돌리기 — 가장 흔한 경우

「누가 실수로 고객사 몇 건을 지웠다」 같은 상황이다.

### 2-1. 먼저 무엇이 없어졌는지 본다

```
cd C:\Users\admin\acctk-ems
node -e "const a=require('C:/Users/admin/ems-backup/20261023/db-20261023/customers.json');console.log('백업에',a.length,'행')"
```

지금 DB 의 행 수는 Supabase 대시보드 → Table Editor 에서 보거나,
`_manifest.json` 의 그 표 `rows` 와 비교한다.

### 2-2. 순서를 지킨다 — FK 가 있는 표는 부모가 먼저

되돌릴 표가 다른 표를 가리키면(외래키) **가리키는 쪽이 먼저 있어야** 들어간다.
이 앱에서 자주 쓰는 순서:

```
engineers · teams · offices          ← 사람·팀·사무실(가장 먼저)
customers                            ← 고객사 (parent_customer_id 가 같은 표를 가리킨다:
                                        is_parent = true 인 행을 먼저 넣어라)
contacts · devices                   ← 고객사 아래
quotes → quote_items · quote_expenses
inquiries → inquiry_messages · inquiry_attachments
service_history → service_engineers · service_attachments · service_install_prep
approval_documents → approval_lines · approval_history
sales_opportunities · sales_activities · holdings → holding_notes
```

거꾸로(자식 먼저) 넣으면 `violates foreign key constraint` 오류가 난다 — **그 오류는
멈추라는 신호다.** 부모를 먼저 넣고 다시 하라.

### 2-3. 되돌리기 — 복사해 쓰는 명령

`scripts/` 에 전용 도구를 두지 않았다(지우거나 덮어쓰는 도구를 저장소에 두면 누가 실수로
돌린다). 아래를 **그때 한 번** 쓰고 지운다. `TABLE` 과 `FILE` 두 줄만 바꾼다.

```
cd C:\Users\admin\acctk-ems
node -e "
const fs=require('fs');
const TABLE='customers';
const FILE='C:/Users/admin/ems-backup/20261023/db-20261023/customers.json';
const DRY = !process.argv.includes('go');            // 끝에 go 를 붙일 때만 실제로 쓴다
const env={};
for (const l of fs.readFileSync('.env.local','utf8').split(/\r?\n/)) { const m=l.match(/^([A-Z0-9_]+)=(.*)$/); if(m) env[m[1]]=m[2].trim(); }
const rows=JSON.parse(fs.readFileSync(FILE,'utf8'));
(async()=>{
  console.log(TABLE, rows.length, '행', DRY?'(연습 — 아무것도 쓰지 않는다)':'(실제로 쓴다)');
  if (DRY) { console.log('첫 행의 칸:', Object.keys(rows[0]||{}).join(', ')); return; }
  for (let i=0;i<rows.length;i+=500) {
    const chunk=rows.slice(i,i+500);
    const r=await fetch(env.NEXT_PUBLIC_SUPABASE_URL+'/rest/v1/'+TABLE, {
      method:'POST',
      headers:{ apikey:env.SUPABASE_SERVICE_ROLE_KEY, Authorization:'Bearer '+env.SUPABASE_SERVICE_ROLE_KEY,
                'Content-Type':'application/json', Prefer:'resolution=merge-duplicates,return=minimal' },
      body: JSON.stringify(chunk),
    });
    console.log(i, r.status, r.ok?'':await r.text());
    if (!r.ok) { console.error('멈춘다 — 위 오류를 사람에게 보여라'); process.exit(1); }
  }
  console.log('끝');
})();
"
```

- **먼저 그냥 돌려 본다**(연습 — 아무것도 쓰지 않는다). 행 수와 칸 이름이 맞는지 본다.
- 맞으면 **닫는 따옴표 뒤에** `go` 를 붙여 다시 돌린다 — 명령 맨 끝이 `" go` 가 된다.
  (`--go` 는 안 된다. node 가 그것을 자기 옵션으로 읽고 `bad option: --go` 로 멈춘다.)
- `resolution=merge-duplicates` 는 **기본키가 같으면 덮어쓰고 없으면 넣는다**(upsert).
  그래서 **이미 있는 행의 최신 수정이 백업 시점으로 되돌아간다.** 지워진 몇 건만 되살리고
  싶으면 `rows` 를 그 몇 건으로 줄여서 돌려라:
  `const rows=JSON.parse(...).filter(r=>[1234,1235].includes(r.customer_id))`
- `service role` 키를 쓰므로 RLS 를 지나지 않는다. **그래서 위험하다** — 표 이름을 두 번 확인하라.

### 2-4. 되돌린 뒤

- 화면에서 눈으로 확인한다(고객사 목록·견적 목록 등).
- 집계 화면(실적 현황·포캐스트)은 브라우저를 새로 고쳐야 캐시가 비워진다.

## 3. DB 전체 복구 — 큰 사고

### 3-1. 7일 안의 일이면: Supabase 일일 백업

1. Supabase 대시보드 → 프로젝트 → **Database → Backups**
2. 되돌릴 시점을 고르고 **Restore**. (유료 플랜이면 특정 시각까지 되돌리는 PITR 이 있다.)
3. **주의**: 복원은 **그 시점 이후의 모든 변경을 버린다.** 복원 전에
   `npm run backup` 을 한 번 돌려 **지금 상태를 먼저 떠 두라** — 그러지 않으면
   「복원해서 옛 자료를 살렸는데 오늘 들어온 자료가 사라졌다」가 된다.
4. 복원이 끝나면 화면에서 로그인해 보고, 실적 현황·결재함이 뜨는지 확인한다.

### 3-2. 7일보다 오래된 것이 필요하면: 일일 백업 + 주간 JSON 보강

일일 백업으로 **구조를 되살리고**(표·RLS·함수), 그 위에 주간 JSON 으로 **오래된 자료를
덮어 넣는다**.

1. 3-1 로 **가장 오래된 일일 백업**을 복원한다(구조가 온전해진다).
2. 필요한 표를 **2-3 의 명령**으로 하나씩 넣는다. **2-2 의 순서**를 지킨다.
3. 각 표를 넣은 뒤 행 수를 `_manifest.json` 과 맞춰 본다.

### 3-3. 프로젝트가 아예 없어졌을 때(최악)

주간 JSON 만으로는 **안 된다** — 표 구조가 없기 때문이다. 순서는 이렇다.

1. 새 Supabase 프로젝트를 만든다.
2. **저장소의 `*.sql` 을 순서대로 실행해 구조를 세운다.** 어느 파일이 적용된 상태인지는
   `docs/audit-2026-10.md` B1 의 표와 각 파일 머리말을 보라
   (`approval_schema.sql` → `inquiries_schema.sql` → … 식으로 기능별이다).
   `db-YYYYMMDD\_schema.json` 에 그때의 표·컬럼·함수 목록이 있으니 빠진 것을 찾는 데 쓴다.
3. 표가 서면 **2-3 의 명령으로 자료를 넣는다**(2-2 순서).
4. 스토리지는 4번으로.
5. `.env.local` 과 Vercel 환경변수의 `NEXT_PUBLIC_SUPABASE_URL`·`ANON_KEY`·`SERVICE_ROLE_KEY` 를
   새 프로젝트 값으로 바꾼다. **키는 회사 비밀번호 금고에서 꺼낸다.**

이 경우는 혼자 하지 마라. 다만 **백업은 전부 여기 있다**는 것이 중요하다.

## 4. 스토리지 파일 되돌리기

파일은 `storage-YYYYMMDD\<버킷>\<경로>` 에 **원래 경로 그대로** 있다.
DB 의 주소 칸(`quotes.pdf_url`·`devices.image_url`·`inquiry_attachments.file_path` 등)이
그 경로를 가리키므로 **같은 버킷·같은 경로로 올리면 화면이 다시 찾는다.**

### 4-1. 한두 개면 — 대시보드로

Supabase 대시보드 → **Storage** → 버킷 선택 → 폴더로 들어가 **Upload file**.
파일 이름을 **그대로** 둬야 한다(이름이 곧 주소다).

### 4-2. 여러 개면 — 명령으로

```
cd C:\Users\admin\acctk-ems
node -e "
const fs=require('fs'), path=require('path');
const BUCKET='quote-pdfs';
const DIR='C:/Users/admin/ems-backup/20261023/storage-20261023/quote-pdfs';
const DRY = !process.argv.includes('go');
const env={};
for (const l of fs.readFileSync('.env.local','utf8').split(/\r?\n/)) { const m=l.match(/^([A-Z0-9_]+)=(.*)$/); if(m) env[m[1]]=m[2].trim(); }
const walk=(d,base='')=>fs.readdirSync(d,{withFileTypes:true}).flatMap(e=>
  e.isDirectory()?walk(path.join(d,e.name), base?base+'/'+e.name:e.name):[{abs:path.join(d,e.name), rel:(base?base+'/':'')+e.name}]);
const files=walk(DIR);
(async()=>{
  console.log(BUCKET, files.length, '파일', DRY?'(연습)':'(실제로 올린다)');
  if (DRY) { files.slice(0,5).forEach(f=>console.log('  '+f.rel)); return; }
  for (const f of files) {
    const body=fs.readFileSync(f.abs);
    const r=await fetch(env.NEXT_PUBLIC_SUPABASE_URL+'/storage/v1/object/'+BUCKET+'/'+f.rel.split('/').map(encodeURIComponent).join('/'), {
      method:'POST',
      headers:{ apikey:env.SUPABASE_SERVICE_ROLE_KEY, Authorization:'Bearer '+env.SUPABASE_SERVICE_ROLE_KEY,
                'x-upsert':'true', 'Content-Type':'application/octet-stream' },
      body,
    });
    console.log((r.ok?'올림 ':'실패 ')+f.rel+(r.ok?'':' '+r.status));
  }
  console.log('끝');
})();
"
```

- 먼저 그냥 돌려 본다(연습 — 파일 목록만 찍는다). 맞으면 **닫는 따옴표 뒤에** `go` 를 붙여 다시 돌린다.
- `x-upsert: true` 라 **같은 경로의 파일을 덮어쓴다.**
- 버킷이 없으면 먼저 대시보드에서 만든다. **공개/비공개를 원래대로** 맞춰야 한다 —
  `_manifest.json` 의 각 버킷 `public` 값이 그때 상태다
  (지금은 `device-images` 와 `notices` 만 공개다).

## 5. 한 번은 연습해 보라

**해 보지 않은 백업은 백업이 아니다.** 한가한 날 30분이면 된다.

1. `npm run backup` 을 돌린다.
2. **아무 영향 없는 표 하나**를 골라 연습한다 — `exchange_rate` 를 권한다
   (환율 기록이고, 중복으로 넣어도 upsert 라 늘지 않는다).
3. 2-3 의 명령을 연습 모드로 돌려 행 수·칸 이름이 나오는지 본다.
4. ` --go` 로 한 번 넣어 보고, 대시보드에서 행 수가 그대로인지 확인한다(덮어썼으니 같아야 한다).
5. 스토리지도 4-2 를 `suggestion-images`(파일 1개)로 연습한다.

여기까지 되면 **진짜 사고가 났을 때 할 일은 표 이름을 바꾸는 것뿐이다.**

## 6. 기억할 것 네 줄

1. 뭔가 지워졌으면 **먼저 `npm run backup` 으로 지금 상태를 떠 둔다.** 복구가 또 지운다.
2. 7일 안이면 Supabase 일일 백업이 가장 깨끗하다. 그보다 오래면 주간 JSON 이 유일하다.
3. **스토리지는 주간 백업에만 있다.** 첨부·PDF·사진은 Supabase 가 대신 지켜 주지 않는다.
4. 넣는 순서는 **부모 먼저**(2-2). FK 오류는 멈추라는 신호다.
