## B. 버그 4 — 커밋 `28946f2`

### B1 사후 실적 모달 깜빡임

**원인 한 줄** — 창이 카드 머리 안에서 그려지는데, 카드(`DashCard`)는 호버에
`translateY(-2px)` 을 걸고 `overflow: hidden` 이다. 조상에 `transform` 이 걸리면
`position: fixed` 의 기준이 뷰포트에서 **그 조상**으로 바뀐다(CSS 의 containing block).

| 잰 것 | 전 | 후 |
|---|---|---|
| 카드 머리에 꽂은 「바탕과 같은 상자」(창 1440×900) | 호버 아님 **1430×900** ↔ 호버 중 **275×328** | (기계는 그대로 — 창이 그 밑에 들어가지 않는다) |
| 모달의 부모 | `DIV.home-cell`(페이지 나무 안) | **`body`** |
| 모달이 DOM 에 붙은 횟수 | — | **1** (렌더 루프가 아니었다) |
| 상자 크기가 바뀐 횟수 / 20번 | — | **0** |

고친 자리는 **공용 바탕 하나**다 — `ModalOverlay` 가 `createPortal(…, document.body)`
로 그린다. 이벤트는 React 나무를 따라 그대로 올라가므로 넣는 쪽의 `stopPropagation` 은
그대로 듣고, context·`.acc-form` 같은 조상 클래스도 children 과 함께 옮겨 간다.
서버에서는 아무것도 내지 않는다(`useSyncExternalStore` — 효과 안 setState 를 쓰지 않는다).

> 「＋ 사후 실적」 단추 자체는 **슈퍼관리자에게만** 선다. 실측 계정은 그 권한이 없어
> 창을 직접 열지 못했다 — 그래서 **그 창이 들어가는 자리**에 같은 상자를 꽂아 쟀다.

## D. 호버·포커스·선택 링 전수 통일 — 커밋 `702f70b`

### D1 — 어디서 뽑았나

견적 작성 「사명」 검색칸의 포커스 모양 그대로다(`app/quote/page.tsx` 의
`.q-box:focus-within` · `.q-input:focus`). `lib/focusRing.ts` 에 토큰으로 두었다.

```
border-color: #234ea2                        ← --color-brand
box-shadow:   0 0 0 3px rgba(35,78,162,0.10) ← --color-brand-ring
outline:      none
```

> ⚠ **판단 필요 — 두께**. 시안 설명은 「파란 **2px** 테두리」인데 **코드의 그 자리는 1px
> 테두리 + 3px 테두리광**이다. 「색값은 그 코드에서 그대로 뽑는다」를 따라 두께도 그
> 자리의 것을 썼다. 2px 로 굵히면 링이 켜질 때 칸이 1px 씩 커져 **줄 전체가 들썩인다**
> (테두리광은 자리를 차지하지 않는다). 바꾸려면 `lib/focusRing.ts` 의 `RING_WIDTH` 한 줄과
> `app/globals.css` 의 링 블록을 함께 고치면 된다.

### D2 · D3 — 전수 조사 표

**① 글자를 넣는 칸** — 전역 규칙 **하나**가 모든 `input`·`select`·`textarea`·
`contenteditable` 을 덮는다(`app/globals.css` 의 「고르는 자리의 링」).
