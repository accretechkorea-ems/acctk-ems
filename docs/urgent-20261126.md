## A. iPhone Safari 화면

### A1 · A2 — 자동 확대

`maximum-scale=1` 을 넣고(`user-scalable=no` 는 **쓰지 않았다** — 두 손가락 확대는 남긴다),
≤768px 에서 입력칸 글자를 **16px** 로 올렸다. 둘 다 있어야 한다: 16px 규칙만 두면 이미
확대된 자리에서 돌아오지 않고, `maximum-scale` 만 두면 확대 자체는 막아도 칸이 작다.

**왜 `!important` 인가 — 전수 조사 결과**

| 어디에 | 몇 곳 |
|---|---|
| 입력 태그(`input`·`select`·`textarea`)에 **바로 붙은** `fontSize` 16 미만 | **80곳** (37파일) |
| 입력칸이 쓰는 **공용 스타일 객체**(`inputStyle`·`fieldStyle`·`field`·`scopeSelect` …) | **56곳** (50파일) |
| 폰 미디어 쿼리로 입력칸을 16 미만으로 덮는 CSS | **0곳** |

전부 인라인이라 보통 규칙으로는 한 곳도 못 덮는다. 그 136곳을 지우면 **PC 디자인이 함께
바뀐다**(13px 칸이 전부 16px). 그래서 **폰 폭에서만** 덮었다 — PC 는 한 픽셀도 안 바뀐다.
체크박스·라디오·범위·색은 글자를 쓰지 않아 뺐고, 단추는 확대를 일으키지 않아 건드리지 않았다.

### A3 — 앱바 회귀 지점

**`f207d63` (2026-11-25 22:38, 「iOS 가로 잘림 대비 · 발주 목록 쪽 나누기 · V8 후속」).**

그 커밋이 폰 규칙만 `app/globals.css`(머리)로 옮기고, PC 기본값은
`components/common/HeaderWrapper.tsx` 의 본문 `<style>` 에 남겼다.

```
머리 (globals.css)        @media (max-width:768px) { .ems-topbar { display: flex } }
본문 (HeaderWrapper)      .ems-topbar, .ems-drawer-wrap { display: none }      ← 뒤에 온다
```

특정도가 같으면 **뒤에 오는 쪽이 이긴다**. 본문은 머리보다 뒤다 → `display:none` 이
**모든 폭에서** 이겼다. `/debug/viewport` 가 `.ems-topbar display:none` 을 그대로 보여 주고
있었다.

→ 기본값을 `globals.css` 의 `@media` **앞**으로 옮겼다. 두 규칙이 한 파일에 차례대로 있다.
`.ems-drawer-wrap` 은 **인라인** `display` 가 있어 살아 있었다(그래서 드로어는 열렸다).

「드로어가 열렸을 때만 숨긴다」는 **두지 않았다** — 드로어는 `fixed·inset 0` 로 위 층
(`Z.sidebarPanel`)을 덮으므로 앱바는 어차피 가려진다. 보이지 않는 규칙을 두면 다음 사람이
그것을 믿고 고친다.

→ `body { background: #fafafa }` (페이지 배경)로 바꾸고 layout 의 `bg-white` 를 걷었다.
로그인처럼 제 배경을 쓰는 화면은 그대로다.

측정 지표도 고쳤다: 「틈이 있나」가 아니라 **「틈이 보이나」**로 센다(짧은 화면은 늘 틈이

## C. 로그아웃 안 됨 — 언제부터 · 누가 · 무엇이

> **2026-11-25 의 `772c96e`** 부터, **로그인한 모든 사람**이, **아바타 메뉴 전체**를 쓸 수
> 없었다. 그 커밋은 사이드바 아바타 메뉴를 `Popover`(포털)로 옮겼다 — 접힌 사이드바가
> `overflow: hidden` 이라 메뉴가 반쯤 잘리던 것을 고치려던 변경이다. 메뉴는 `document.body`
> 로 나갔는데, 그 자리를 지키던 옛 코드 한 줄이 그대로 남았다:
> `useOutsideClick(meRef, () => setMeOpen(false), meOpen)`.
> `meRef` 는 **아바타를 감싼 div** 다 — 포털된 패널은 그 **밖**이다. 그래서 패널 안을 눌러도
> 「바깥을 눌렀다」로 보고 **mousedown 단계에서 메뉴를 닫았다**. click 은 mousedown 과
> mouseup 이 **같은 요소**에서 나야 생기므로, 단추가 그 사이에 사라져 **click 이 아예 나지
> 않았다**. 마우스도 터치도 mousedown 을 지나므로 PC·폰이 똑같이 당했다.
> 눌러도 아무 일이 없고 오류도 없다 — 신고된 모습 그대로다. 같은 이유로 **「정보 수정」도
> 눌리지 않았다**.

측정으로 못을 박았다: 「로그아웃」에서 `pointerdown` 1건 · `mousedown` 1건 · **`click` 0건**.

### 함께 고친 둘째 결함

`handleLogout` 은 2026-09-23 부터 이랬다.

```ts
await supabase.auth.signOut()
window.location.href = '/login'
```

`signOut()` 은 서버에 토큰을 거두러 **망을 탄다**. 끊기거나 이미 만료된 토큰이면(403) 거부되어
**다음 줄이 실행되지 않는다**. 로그아웃 요청만 막고 눌러 재현했다 — 주소가 그대로였다.
더 나쁜 것: **멈춘 요청이 supabase 의 auth 잠금을 쥐고 있어** 폴백으로 둔
`signOut({ scope: 'local' })` 까지 함께 멈췄다.

→ 로그아웃을 **한 함수**로 모았다(`lib/auth/logout.ts`). 사이드바 두 단추와 자동 로그아웃이
같은 함수를 쓴다(전에는 두 자리가 달랐다 — 자동 쪽만 try/catch 뒤에 꼭 화면을 옮겼다).

1. `signOut()` 을 **2.5초까지만** 기다린다.
2. 거뒀든 못 거뒀든 `sb-…auth-token` **쿠키·저장소를 직접 지운다**(SDK 를 거치지 않으므로
   잠금과 무관하다). 쿠키를 두고 떠나면 더 나쁘다 — `/login` 에서 미들웨어가 세션을 보고
   대시보드로 되돌려 보낸다.
3. 앱이 든 자료(본인·알림·결재함)를 버리고 **`replace`** 로 나간다(뒤로 가기 자리를 남기지 않는다).

**뒤로 가기** — bfcache 로 **되살아난** 보호 화면도 막는다(`guardRestoredPage`). 되살아난
순간에만 세션을 다시 보고, 없으면 로그인 화면으로. 못 물어보면 그대로 둔다.

## D. 비밀번호 초기화

- 직원 관리 표에 **「비밀번호」 열**과 「비밀번호 초기화」 단추. 확인창은 공용
  `ConfirmDialog` 로 지시한 문구 그대로.
- `POST /api/admin/reset-password` — 관리자만. **이 앱의 등급은 `superadmin` · `member`
  둘뿐이라 「admin 이상」 = 직원 관리를 여는 그 권한**이다(`canManageEngineers`).
- 임시 비밀번호는 **서버가** 만든다(`lib/tempPassword.ts`). 영문 대소문자 + 숫자 10자,
  헷갈리는 `0 · O · 1 · l` 을 뺀 **58자**에서 뽑는다. **치우치지 않게** 뽑는다 — 256 이 58 로
  나누어떨어지지 않아 그냥 나머지를 쓰면 앞쪽 글자가 더 자주 나온다(배수를 넘는 값은 버린다).
- **값은 응답에만 있다.** DB 에도 로그에도 없다 — 하네스가 DB 로 가는 글과 로그 줄을 훑어
  그 글자가 없는 것을 센다.
- 화면: 큰 글씨 + 「복사」. 닫으면 다시 못 본다고 창이 말한다(복사가 막히면 알려 준다 —
  글자는 화면에 남아 옮겨 적을 수 있다).
- `engineers.must_change_password` 가 켜지면 미들웨어가 그 사람을
  `/account/change-password` 로 보낸다. 그 조회는 **퇴사 판정과 같은 한 줄**에 얹었다 —
  화면 이동마다 조회가 늘지 않는다. 그 화면은 지금 비밀번호를 묻지 않는다(임시값으로 이미
  들어와 있다). 저장하면 표식이 꺼진다. 길이 규칙은 기존 `PASSWORD_MIN` 그대로.

### 사건 기록 — **판단 필요**

지시는 「사건 기록(누가·누구를·언제)」인데 **관리자 행위를 담는 표가 이 앱에 없다**
(`customer_events` 는 고객 전용이다). 새 표를 만드는 것은 지시에 없어, 지금은 **서버 로그
한 줄**로 남긴다(누가·누구를·언제·표식 여부. 값은 없다). 표가 필요하시면 만들겠다.

### 실측

`[검증용]` 계정은 **만들지 않았다**(지시 D6). 대신 **쓰기가 없는 것만** 쟀다 —
member 계정으로 `POST` 두 번(제 번호로 · 번호 없이): 둘 다 **403 Forbidden**, 응답에 임시값
없음. 막히면 비밀번호도 표식도 건드려지지 않으므로 이 측정은 아무것도 쓰지 않는다.
나머지(임시값 모양·강제 이동 흐름·표식 켜고 끄기)는 하네스가 본다 —
임시값은 **400개를 실제로 만들어** 길이·금지 글자·중복·치우침을 센다.

## E. CSP

`connect-src` 에 **`data:` 한 낱말**만 더했다. 다른 지시어는 손대지 않았다.

react-pdf 가 쓰는 `yoga-layout` 이 wasm 을 base64 data URL 로 품고 `fetch(dataUrl)` 로 먼저
집는다. 막히면 동기 디코딩으로 되돌아가 **PDF 는 그대로 돌지만** 브라우저가 위반 보고를
콘솔에 두 줄 남겼다. 같은 머리글의 `font-src`·`img-src` 는 이미 `data:` 를 받고 있고,
`connect-src` 가 막는 것은 「어디로 보내는가」인데 `data:` 에는 보낼 곳이 없다.

**실측** — 고친 뒤 견적·활동 현황·쇼룸·홈 네 화면 콘솔 **0건**.

새 하네스 `scripts/csp-check.js` — 위험한 낱말(`unsafe-*` · `data:` · `blob:`)이 **어느
지시어에** 있는지를 못 박는다(한 낱말이 긴 한 줄에 묻혀 조용히 늘어나는 것을 막는다).
맨 `*` 와 `https:` 통짜가 없는 것도 본다.
