# 죽은 파일 · 죽은 import · 안 쓰는 export (2026-11-27 야간3 9-1)

**지운 것은 없다.** 네 가지를 셌는데 **확실히 죽은 것이 하나도 없었다** — 아래가 그 근거다.
지시문의 「확실한 것만 지운다」를 지켰다.

재는 법 — `tsc --noEmit`(0건) · `npx eslint .`(0 오류 / 30 경고 = 기준선 그대로) ·
저장소 전 파일(`app` · `components` · `hooks` · `lib` · `scripts`)을 서로 훑는 조사 스크립트 둘.
조사 스크립트는 담지 않았다(2026-11-27 의 「조사용 임시 파일은 담지 않는다」와 같은 규칙).

## 1. 죽은 import — **0건**

`eslint` 가 `@typescript-eslint/no-unused-vars` 를 **오류**로 잡는 설정이고, 지금 오류가 0 이다.
남은 경고 30건은 전부 `react-hooks/exhaustive-deps` 와 setState-in-effect 로
`scripts/lint-baseline.json` 의 기준선(maxWarnings 30)과 **정확히 같다**. 늘지도 줄지도 않았다.

### ① `lib/partSearch.ts` — 7-5 에서 찾지 못했던 「부품 검색」이 여기 있다

7-5 보고서(`docs/quote-last-price-20261127.md`)에 「지시문의 **지도 부품 검색** 은 이 저장소에서
찾지 못했다」고 적었다. **틀렸다 — 모듈은 있고 화면만 없다.**

`searchParts(품번 또는 품명)` 가 `quote_items` 의 **견적 시점 스냅샷**(`part_code`·`product_name`)으로
「이 부품이 어느 업체에 나갔나」를 돌려준다. 가격표가 개정돼도 그때 나간 품번 그대로 찾히도록
`price_list` 를 경유하지 않는다. `MIN_QUERY_LEN = 2`, 상태는 `ORDERED_STATUSES` 로 거른다.

→ **지울 파일이 아니다.** 붙일 자리를 정하는 것이 다음 일이고, 그것이 7-5 의 「판단 필요」였다.

### ② `lib/equipmentName.ts` — 라인업 가르기 규칙

품명 한 줄을 라인업·모델·구성으로 가르고 **확신도(sure)** 를 함께 돌려준다. 7-3
(`docs/lineup-pending-20261127.md`)이 다루는 그 일의 순수 함수다. 읽던 스크립트가 임시
파일이라 함께 지워졌을 뿐, **규칙 자체가 자료**다. 지우면 그 규칙이 사라진다.

### ③ `lib/semiContact/index.ts` — 묶음 파일 + 혼자 남은 함수 하나

`export * from './fields' …` 넷에 더해 `apiErrorText(status, body, fallback)` 하나를 **스스로**
들고 있다(401·403 을 한국어로 바꾸는 자리). 그 함수를 부르는 곳이 없다 — 화면이 자기 문구를
따로 쓰고 있다는 뜻이다. 묶음 파일을 지우면 그 함수도 같이 사라지므로 남긴다.
**합치려면** 화면의 문구를 이 함수로 모으는 쪽이 맞다(지우는 쪽이 아니다).

## 3. 파일 밖에서 안 쓰이는 **값** export — 225개 / 90여 파일

`export` 를 뗄 수 있다는 뜻이지, 코드가 죽었다는 뜻은 아니다 — 대부분 **같은 파일 안에서**
쓰인다. 타입 export(370개)는 셈에서 뺐다(붙어 있어도 번들에 남지 않는다).

**지금 손대지 않는다.** 까닭 둘:

1. `export` 를 떼면 **하네스가 못 읽는다.** 하네스 103개는 `ts.transpileModule` 로 모듈을 그대로

2. 90여 파일을 한꺼번에 고치면 **이 밤의 다른 절과 섞인다.** 되돌릴 때 어느 줄이 어느 절인지
   가릴 수 없게 된다.

→ 할 거리로 남긴다: 「`boxes.ts` 11개부터 한 파일씩, 하네스가 읽는 것만 남기고 떼기」.
