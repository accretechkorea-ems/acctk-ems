## B. 담당자 카드 — **한 벌**이 되었다

2026-11-25 에 PC 는 왼쪽 열의 세로 카드(V8)가 되었는데, 폰은 가로 띠의 **칩**이 그대로

[components/customer/ContactList.tsx](components/customer/ContactList.tsx) 하나로 모았다.
어느 폭에서나 한 사람은:

```
  이름(600)  직급 · 부서
  📱 휴대폰(없으면 ☎ 회사 전화)   ← tel:
  ✉ 이메일                        ← mailto:      (없으면 「—」)
```

폭으로 갈리는 것은 **셋뿐**이고 전부 그 부품의 CSS 에 있다:

| | PC | 폰(≤767) |
|---|---|---|
| 수정 | 호버·포커스의 ✎ | **카드를 누르면** 열린다(호버가 없다. 작은 ✎ 를 겨누게 하지 않는다) |
| 접기 | 높이 고정된 띠만 「더보기 +N」 | 접지 않는다 |
| ＋ | 머리줄 아이콘 | 목록 아래 **한 줄짜리 단추** |

## G. 판단 반영

### G1 「납품 예정」 장비 줄의 **주인**

[lib/deviceOwner.ts](lib/deviceOwner.ts) 한 곳이 정한다:

| 차례 | 주인 | 홈 할 일 | 사업장 화면 |
|---:|---|---|---|
| ① | `source_quote` **작성자** | 그 사람에게 | 늘 보인다 |
| ② | 없으면 `devices.created_by` | 그 사람에게 | 늘 보인다 |
| ③ | 둘 다 없음 | **안 띄운다** | **여기에만** 선다 |

②를 위해 칸 하나가 필요하다 — [db/devices_created_by_20261127.sql](db/devices_created_by_20261127.sql)
(**미적용**, 아래 참조). 없으면 발주를 거치지 않고 손으로 넣은 줄이 **누구의 할 일도 아닌 채**
떠다닌다(지금 홈은 ①만 보므로 아무에게도 안 보인다).

⚠ **옛 줄은 채우지 않는다** — 작성자가 어디에도 남아 있지 않다. 틀린 사람에게 할 일을
붙이는 것보다 규칙 ③으로 떨어뜨리는 쪽이 낫다(SQL 에 `update` 문이 없다).
0·음수·글자 id 는 걸러 낸다 — 그대로 믿으면 엉뚱한 사람에게 할 일이 붙는다.

### G2 통계 엑셀 「종류」 판정 차례

지시문의 규칙으로 맞췄다. **사실을 먼저** 본다 — 분류 글자는 사람이 고르는 칸이라 자주
비거나 틀리고, 품목은 견적을 쓰며 쌓인 사실이다.

| 차례 | 조건 | 종류 |
|---:|---|---|
| ① | 수리 건 **연결**(`repair_id`) | 수리 |
| ② | 품목에 **base** 줄 | 장비 |
| ③ | 본체 없이 **option** 줄만 | 업그레이드 |
| ④ | 분류가 **소모품·부품** | 소모품 |
| ⑤ | 그 외 | 기타 |

**보고서 규칙과 달랐던 것 셋**(지시대로 이쪽으로 맞췄다):

| | 전 | 후 |
|---|---|---|
| 분류 이름이 「수리」인데 연결이 없다 | 수리 | **기타**(수리는 연결로만) |
| 분류가 「업그레이드」인데 본체 줄이 있다 | 업그레이드 | **장비**(본체를 판 건이다) |
| 본체도 옵션도 아닌 품목만 있다 | 소모품 | **기타**(잘못 세는 것보다 「모르겠다」가 낫다) |
