## 어떻게 쟀나

- 운영 DB 를 **읽기만** 했다(service role, select 뿐). 쓰기·삭제 없음.
- 코드는 읽어서 **그 값을 넣는 자리**를 찾았다. 근거는 `파일:줄` 로 적는다.
- 숫자는 **지워지지 않은 줄**(`deleted_at is null`) 기준이다.
- 「사실」과 「추측」을 나눈다. 세어 본 것만 사실로 적는다.

조사 범위: `customers` · `devices` · `contacts` · `quotes` · `inquiries` · `leads`
· `sales_activities` · `service_history` · `engineers`.

## ⑤ 하지 않은 것 · 알 수 없는 것

- **백필을 하나도 하지 않았다.** 글자를 연결로 바꾸는 일은 사람이 보고 정해야 한다
  (「NSK KOREA」와 「NSK KOREA (CHANGWON PLANT)」가 같은 사업장인지 코드가 모른다).
- `contacts.department` 는 고를 목록을 만들 근거가 없다 — 회사마다 부서 이름이 다르다.
  빈 곳이 1,242건인 것은 **필요 없어서일 수도 있다**(추측).
- `quotes.category`·`form_kind` 가 빈 건은 **전부 옛 견적이다**(사실 — 분류가 빈 85건 중
  가장 최근이 2026-10-18, 양식이 빈 92건 중 가장 최근이 2026-10-20 에 만들어졌다).
  그 뒤에 만든 견적은 둘 다 채워져 있다 — **입구는 이미 닫혀 있다.**
- 같은 시리얼 186건이 **정말 같은 장비인지**는 보지 않았다 — 사람이 봐야 한다.
- 이 조사는 **지금 값**만 본다. 「언제부터 더러워졌는가」는 `customer_events` 가 생긴
  2026-11-20 뒤의 일만 알 수 있다.
