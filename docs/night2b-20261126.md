## 3. 실측이 잡은 **진짜 버그** — 실주 처리가 전부 막혀 있었다

`lost_reasons` 를 적용한 뒤 포캐스트에서 「경쟁사」를 사유로 고르고 저장하면 **전부 거절**됐다.

```
[opportunity] mark lost failed
{ code: 23514, message: new row for relation "sales_opportunities"
  violates check constraint "sales_opportunities_lost_reason_check" }
```

까닭: 옛 **글자** 칸 `sales_opportunities.lost_reason` 에 값 목록을 못 박은 CHECK 가 그대로 남아 있다.
지금 들어 있는 값은 셋뿐이다 — 「사양·기술 · 경쟁사 선정 · 가격」(조회로 확인). 새 사유 목록의 이름이
거기 없으니 **표를 적용해도 실주가 되지 않는다.** 화면만으로는 보이지 않는 자리였다.

두 쪽을 다 두었다.

1. **`db/lost_reason_drop_check_20261126.sql`(미적용)** — 그 제약을 뗀다. 값을 지키는 일은 이제
   FK(`lost_reason_id → lost_reasons`)가 한다. 글자 칸은 **지난 줄의 기록**으로 남긴다(지우지 않는다).
   파일 [0단계] 조회로 걸린 제약을 눈으로 먼저 본다.
2. **코드 폴백** — `markLost` 가 23514 를 받으면 **글자 칸을 빼고 id 로만** 적는다(42703 폴백과 같은 모양).

## 4. 판단 필요 · 못 한 것

### 판단 필요 ① — 「본체 묶음」의 값 (②)

지시의 글자는 `group_kind main` 이었는데, 이 DB 의 `group_kind` 는

```sql
check (group_kind in ('base', 'option', 'include'))   -- quote_category_template_schema.sql:327
```

로 묶여 있다. `'main'` 은 **들어갈 수 없는 값**이라 그대로 쓰면 판정이 **영원히 거짓**이 되어
납품 예정 장비 섹션이 한 번도 뜨지 않는다. 그래서 「본체 묶음」을 **`'base'`**(= 「1. 본체 + 기본 구성」)로
읽었다. 다른 값을 뜻했다면 `lib/deliveryPending.ts` 의 `MAIN_GROUP_KIND` **한 줄**만 고치면 된다.

### 못 한 것 ① — C2(견적 ↔ 포캐스트 연결·해제)

연결·해제는 **견적 쪽 줄을 고친다**. 운영 견적으로 하면 운영 자료를 건드리는 것이고, [검증용] 견적을
새로 쓰려면 **견적 번호를 발급**해야 하는데 그 번호는 **순번을 먹고 되돌릴 수 없다**(줄을 지워도 번호에
구멍이 남는다). 「운영 데이터 쓰기 금지」와 「만든 것만 지운다」를 함께 지킬 길이 없어 **하지 않았다**.
코드 쪽은 하네스(`scripts/quote-forecast-check.js` 등)가 보고 있다.
하려면 — 버려도 되는 번호 구간을 하나 정해 주시면 그 안에서 재겠다.

### 못 한 것 ② — 「견적 만료 → 사유 입력 → 줄 사라짐」 / F③(견적에 할 일 걸기)

### 못 한 것 ③ — [검증용] 회사·사업장 만들기

주소 칸이 **카카오 우편번호 검색 전용(readOnly)** 이고 그 키가 3100 을 거부한다(5절). 그래서 사업장 하나를

**고객사 — 「카카오 지도 SDK 로드 실패」.** 카카오 JS 키에 `http://localhost:3000` 만 사이트 도메인으로

```
Referer http://localhost:3000 → 200
Referer http://localhost:3100 → 401
```

사용자 개발 서버(:3000)와 운영에서는 나지 않는다. 고칠 코드가 없다 — 재려면 콘솔에 3100 을 더해야 한다.

**견적서 — CSP `connect-src` 가 `data:` 를 막는다(판단 필요 ②).**
react-pdf 가 쓰는 `yoga-layout` 의 wasm 이 base64 data URL 로 묶여 있고, 그 모듈은 `fetch(dataUrl)` 로
먼저 집는다. 막히면 **동기 디코딩으로 되돌아가므로 PDF 는 그대로 돈다** — 브라우저가 위반 보고를 두 줄
남기는 것이 전부다. 자바스크립트로 잡을 수 있는 오류가 아니다.

`next.config.ts` 의 `connect-src` 에 `data:` 를 **더하지 않았다.** 보안 머리글을 넓히는 일은 지시에 없었고
가장 보수적인 쪽을 골랐다. 지우고 싶으시면 한 낱말이면 된다:

```diff
- "connect-src 'self' https://*.supabase.co …"
+ "connect-src 'self' data: https://*.supabase.co …"
```

같은 머리글의 `font-src`·`img-src` 는 이미 `data:` 를 받고 있다(data URL 은 내용을 스스로 들고 있어
밖으로 빼낼 길이 되지 않는다). 더할지는 정해 주시면 그대로 한다.

## 6. ⑤ — 꺾쇠 한 글자가 전 화면의 첫 그림을 버리게 했다

`components/common/HeaderWrapper.tsx` 의 `style` 태그 **주석 안**에 `<style>` 이라고 적혀 있었다.
서버는 style 안의 여는 꺾쇠를 CSS 이스케이프로 피해 적고(`<\73 tyle>`), 브라우저는 글자를 그대로 넣는다.
두 글자가 달라져 React 가 트리를 버리고 다시 그렸다 — **로그인 영역의 모든 화면**에서.

```
+ {"...26): 이 <style> 은 **본문 안에서** 그려진다..."}      ← 브라우저
- {"...26): 이 <\73 tyle> 은 **본문 안에서** 그려진다..."}   ← 서버
```

같은 실측에서 활동 현황의 「두 children 이 같은 key, `A/S`」 **열두 건**도 잡혔다. 2026-11-26 에
`activity_types` 에 'A/S' 를 더했는데 `SERVICE_TYPES` 에도 'A/S' 가 있어 합친 순서 목록에 이름이 두 번
들어갔다 — 카드가 같은 줄을 두 번 그렸다. 집계(`counts`)는 이름을 열쇠로 쓰므로 **한 줄이 맞다**:
`activityTypeOrder` 가 겹치는 이름을 지운다.

둘 다 `scripts/hydration-check.js` 가 지킨다 — style 태그 안의 꺾쇠(24개 블록 전수)와 순서 목록의 이름 중복.
