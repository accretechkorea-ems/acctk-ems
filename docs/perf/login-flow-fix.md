# 로그인 직후 첫 로딩 — 무엇이 느렸고 무엇을 고쳤나 (2026-10-23)

이미 로그인한 뒤 화면을 옮기는 것은 빠른데 **로그인 직후 첫 화면**만 느렸다.
`npm run perf -- --login` 으로 구간을 갈라 재어 보니, 같은 일을 **두 벌** 하고 있었다.

원자료: 전 `2026-10-23-1149-login.json` · 후 `2026-10-23-1152-login.json`
(각각 찬 캐시 3회 + 더운 캐시 3회, 운영 빌드 `next start -p 3100`)

## 재 보니 — 사슬이 두 벌이었다

찬 캐시 대표 회차(「로그인」 누름 = 0):

| # | 요청 | 시작 → 끝 | 누가 부르는가 |
|---|---|---|---|
| 1 | `auth:token` | 80 → 573 | 로그인 |
| 2 | `engineers ?email` | 557 → 756 | **로그인 화면**이 갈 곳을 정하려고 |
| 3 | `teams` | 755 → 946 | 같은 화면의 `withTeamPerm` — ②가 끝나길 기다렸다 |
| 4 | `/dashboard ?_rsc` | 935 → 1,041 | `router.push` |
| 5 | `/dashboard ?_rsc` | 1,045 → 1,111 | **`router.refresh()` — 같은 것을 또** |
| 6 | `auth:user` | 1,177 → 1,262 | **MeProvider 가 처음부터 다시** |
| 7 | `engineers ?email` | 1,261 → 1,363 | **두 번째** (컬럼이 달라 캐시가 안 걸렸다) |
| 8~ | 카드 조회 8건 | 1,369 → 1,628 | 홈 |

리다이렉트는 **0번**이었다(소프트 이동 한 번). 문서가 두 단으로 튀는 문제는 없었다.
`/login` 이 무거운 것을 불러오지도 않았다(흐름 전체의 새 JS 38KB).

문제는 셋이었다.

1. **본인 확인 사슬이 두 벌** — 로그인 화면이 `engineers`+`teams` 를 읽어 갈 곳을
   정하고, 도착한 화면의 `MeProvider` 가 `auth/user`+`engineers` 를 또 읽었다.
2. **teams 가 engineers 뒤에 줄을 섰다** — `teams` 는 내가 누군지와 무관한데
   `withTeamPerm` 이 engineers 결과를 받아서야 불렀다.
3. **`router.refresh()` 가 RSC 를 한 번 더 받았다** — `push` 가 이미 새 쿠키로 받아온 것을.

## 고친 것

| 곳 | 고친 내용 |
|---|---|
| `lib/appData/me.ts` | `loadTeamPerms()` 를 메일을 알아내기 **전에** 띄워 engineers 와 나란히 보낸다 |
| `lib/appData/me.ts` | `auth.getUser()`(Auth 서버 왕복) → `getSession()`(그 자리에서 읽기). 세션이 비었을 때만 `getUser()` 로 떨어진다 |
| `app/login/page.tsx` | 자기 조회를 버리고 `invalidateMe()` + `loadMe()` 를 쓴다 → 도착한 화면의 MeProvider 는 **조회 0건** |
| `app/login/page.tsx` | `router.refresh()` 제거 — 화면들이 모두 `'use client'` 라 다시 받을 RSC 가 없다 |

`getSession()` 을 써도 되는 이유 — 브라우저에서 얻은 메일은 **어느 행을 달라고 할지**
고르는 데만 쓰고, 무엇이 돌아오는지는 서버의 RLS 가 정한다. 토큰을 스스로 위조해도
남의 자료는 열리지 않는다. **서버**(`app/api/**`)는 그대로 서명을 검증한다
(`lib/sessionEmail.ts`).

## 전후 (중간값 3회)

`auth:token` 자체는 회차마다 150~500ms 로 흔들린다(Auth 서버 사정이고 우리가 고친
곳이 아니다). 그래서 **토큰 응답이 끝난 때를 0 으로** 다시 재 둔다.

### 찬 캐시(첫 방문)

| 지점 | 전 | 후 | 차이 |
|---|---|---|---|
| 본인 확인 사슬 끝 | 689ms | **165ms** | −524ms |
| 첫 카드 조회 시작 | 687ms | **305ms** | −382ms |
| 주소가 바뀐 때 | 558ms | **275ms** | −283ms |
| 껍데기(사이드바) | 584ms | **299ms** | −285ms |
| 마지막 요청 끝 | 1,055ms | **532ms** | −523ms |

### 더운 캐시(두 번째 로그인)

|---|---|---|---|
| 본인 확인 사슬 끝 | 669ms | **144ms** | −525ms |
| 첫 카드 조회 시작 | 670ms | **269ms** | −401ms |
| 주소가 바뀐 때 | 535ms | **238ms** | −297ms |

### 누름부터 센 값(토큰 흔들림 포함)

| 지점 | 찬 캐시 전 → 후 | 더운 캐시 전 → 후 |
|---|---|---|
| 껍데기(사이드바) | 1,157ms → 569ms | 914ms → 465ms |
| 네트워크 조용해짐 | 3,228ms → 2,325ms | 2,983ms → 2,305ms |
| 자료 요청 수 | 14건 → **12건** | 14건 → **12건** |
| `auth/user` | 93~96ms | **없음** |
| `/dashboard?_rsc` | 2번 | **1번** |

「조용해짐」에는 측정 도구가 기다리는 침묵 1,500ms 가 들어 있다 — 실제로 자료가 다
들어온 때는 「마지막 요청 끝」이다.

## 남은 것

- 후 타임라인에서 카드 조회는 사슬이 끝난 **122ms 뒤**에 시작한다. 이것은 조회를
  기다리는 시간이 아니라 React 가 그 화면을 올리는 시간이다 — 더 당길 것이 네트워크
  쪽에는 없다.
- `auth:.well-known/jwks.json` 은 아직 한 번 나간다(78ms). 다른 곳에서 토큰을 검증할
  때 받는 것이고, 카드 조회와 **나란히** 가므로 사슬에 들지 않는다.
